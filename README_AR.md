# WEZTY Android — تجهيز بناء APK وتأمين Firestore

هذه حزمة تغليف لنسخة WEZTY Preview v4 الحالية داخل Android عبر Capacitor. لا تستبدل النسخة المنشورة قبل الاختبار والموافقة.

## محتويات الحزمة
- `www/index.html`: نسخة الموقع الحالية.
- `capacitor.config.json`: هوية التطبيق `com.wezty.app` واسمه WEZTY.
- `.github/workflows/android.yml`: بناء Debug APK تلقائياً على GitHub Actions.
- `firestore.rules`: قواعد Firestore مقيّدة بحسابي WEZTY المعتمدين.

## أولاً: نشر قواعد Firestore
1. افتح Firebase Console ثم مشروع `zozo-41d24`.
2. افتح Firestore Database ثم تبويب Rules.
3. خذ نسخة من القواعد الحالية واحتفظ بها خارج Firebase.
4. افتح ملف `firestore.rules` الموجود في هذه الحزمة وانسخ محتواه بالكامل إلى محرر Rules.
5. راجع القواعد ثم اضغط Publish.

**ماذا تسمح القواعد؟**
- الحساب ذو UID المنتهي/المعرّف `DmbbqyG9t2SauNcV2v9LJGFXvYE3` فقط يستطيع إنشاء/تعديل محتوى الإدارة `wezty_admin/content`.
- الحسابان المعتمدان فقط يستطيعان قراءة محتوى الموقع واستخدام مستند `message_reads` ومستند اللعبة `shared_games/zozo_know_game`.
- الحذف ممنوع، وأي مسارات أخرى مرفوضة.
- الحسابات المجهولة القديمة لن تستطيع الوصول بهذه القواعد. لا تحذفها؛ فقط اعلم أن هذه القواعد لا تسمح لها بقراءة/كتابة البيانات.

**ملاحظة أمنية مهمة:** قواعد Firestore تمنع الحسابات الأخرى من الوصول، وتحمي إعدادات الإدارة من تعديل حساب المشاهدة. لكن مستند اللعبة المشترك يسمح للحسابين المعتمدين بتحديثه؛ اختيار دور اللاعب داخل الواجهة ما زال اختياراً محلياً، وليس إثبات هوية مستقلّاً لكل دور.

## ثانياً: بناء APK عبر GitHub
1. أنشئ مستودع GitHub خاصاً (Private) أو استخدم مستودعك الحالي بعد أخذ نسخة احتياطية.
2. ارفع **محتويات** هذا المجلد إلى جذر المستودع، بحيث يظهر مجلد `.github/workflows` في الجذر.
3. افتح تبويب Actions.
4. اختر `Build WEZTY APK` ثم `Run workflow`، أو ادفع commit إلى فرع `main`.
5. انتظر انتهاء التشغيل بحالة نجاح.
6. افتح نتيجة التشغيل وحمّل Artifact باسم `WEZTY-debug-APK`.
7. فك ملف ZIP الناتج وستجد `app-debug.apk`.

## ثالثاً: الاختبار قبل الاعتماد
- سجّل الدخول بحساب Admin وتأكد من ظهور لوحة الإدارة وحفظ الرسائل والأسئلة والعجلة والثيم وSecret Zone.
- سجّل الدخول بحساب Viewer وتأكد من عدم ظهور لوحة الإدارة، ومن إمكانية قراءة المحتوى واستخدام الرسائل واللعبة.
- جرّب تسجيل الخروج ثم الدخول بالحساب الآخر على نفس الجهاز.
- اختبر مزامنة اللعبة وقراءة الرسائل بين الجهازين.
- إذا ظهر `auth/unauthorized-domain` داخل التطبيق، أضف `localhost` إلى Firebase Authentication → Settings → Authorized domains.

## تنبيهات
- لم يتم بناء APK فعلي داخل بيئة العمل؛ هذه الحزمة تجهّز البناء على GitHub Actions.
- الناتج Debug APK للاختبار فقط، وليس إصداراً نهائياً موقّعاً للنشر في المتجر.
- لا تضع كلمات المرور أو مفاتيح التوقيع الخاصة داخل الملفات أو المستودع.
- لا تحذف المستخدمين المجهولين أو بيانات Firebase القديمة قبل التأكد من عدم اعتماد الموقع عليها.
- نشر قواعد Firestore خطوة مستقلة تتطلب دخولك إلى Firebase Console وموافقتك؛ لم يتم نشرها تلقائياً.
